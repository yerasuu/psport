# Packaging psport

A release is built from one tag. Which files it carries, and what each one has to carry for the licences, is
in [LICENSES.md](../../LICENSES.md), section "Release contents". This page is the checklist.

## Before the tag

1. `python3 tools/check_licenses.py`: the manifest matches the tree, every licence has its text in `LICENSES/`,
   every vendored tree and tracked file belongs to a component. It reports; `--strict` exits 1 on any finding.
   The night script runs it in report mode (`licenses-report.txt`).
2. A new component (a vendored tree, a ported file, a font, an asset) goes into `LICENSES.json` and
   `LICENSES.md` in the commit that brings it, with its licence text in `LICENSES/` when the licence is new
   and its source in `FORK.md` or `gpu/VENDOR.txt`. A licence GPL-2.0 cannot absorb (Apache-2.0, GPL-3.0-only)
   is an owner decision before the code lands.
3. Components marked `"review": "pending"` are either resolved or named in the release notes.
4. `VERSION`, `tag-changelog/vX.Y.Z.md` and the tag `vX.Y.Z` agree; the release workflow and the Windows publish
   job refuse a tag that does not match `VERSION`.

## Linux bundle

`tools/bundle.sh PORT TAG DIR` (run by the release workflow on `packaging/port.nix` built with `--arg withNet
false`) writes `DIR/psport-TAG-x86_64.tar.zst` and its `.sha256`:

- programs, `libpsport-gpu.so`, `run.sh`, `scripts/`, `patches/`, the FSR 4 asset scripts in `tools/`;
- `lib/`: every library the programs link from the Nix store, with the store's glibc and its loader;
- `LICENSE`, and `LICENSES.md`, `LICENSES.json` and `LICENSES/` as they are in the tree (`packaging/port.nix`
  installs them);
- `THIRD-PARTY-NOTICES` and `SOURCES.txt`, generated by `packaging/licences.nix` and
  `packaging/licences.py`: licence, source URL and hash of each library, the licence files of its source (the SPDX
  text when it has none), the code compiled in from the tree and from store packages, and the written source offer
  (GPL-2.0 section 3(b), LGPL-2.1 section 6(c), three years). `licences.py` fails the bundle when a GPL, LGPL or
  MPL component has no licence text or no source URL.
- no online module (`PS_BUNDLE_NET=1` keeps it for a bundle that is not redistributed) and no Vulkan loader.

`tools/check_bundle_licences.sh` runs inside `bundle.sh` and again on the archive in the workflow; besides what
the bundle must not hold, it fails when the licence files are missing or `THIRD-PARTY-NOTICES` lacks an entry of
`packaging/vendored.txt`. With `--port`
it checks the build in the store before the binary cache publishes it. Locally, `bash tools/check_bundle_licences.sh
psport-TAG-x86_64.tar.zst` repeats the check.

The AppImage (`packaging/appimage.sh`, `packaging/default.nix`) is built locally and not published. It carries the
Nix closure, the licence files and generated notices that also list dxil-spirv, AMD's API headers in
`fsr4cap.exe` and, in a build with `DLSS_SDK_ROOT`, the DLSS bridge. `PS_PACKAGE_NET=1` adds the online module for
local use only.

## Windows bundle

`tools/win32-bundle.sh` (the `windows.yml` build job, MSYS2 CLANG64) writes `psport-windows-VERSION-COMMIT-x86_64.zip`:
the four programs, the CLANG64 DLLs in their PE import closure whose package licence is on the script's
GPL-2.0-compatible allow-list, `LICENSE.txt`, `LICENSES.md`, `LICENSES.json`, `LICENSES/`, `THIRD-PARTY-NOTICES.txt` (one entry per package with the licence
files it installs, then the code from this tree under its own licence), `SOURCES.txt` (written offer, package
versions and source URLs) and `BUILD-INFO.txt` (DLLs included, DLLs left out and why). `vulkan-1.dll` is the
GPU driver's. FFmpeg is psport's own LGPL-2.1-or-later build from `packaging/windows/ffmpeg/PKGBUILD`; the
sources of the DLLs built from psport's PKGBUILDs are published beside the zip in `...-sources`, with the
licence files next to each PKGBUILD (`LICENSE.MINGW-packages`, the BSD-3-Clause notice of the MSYS2 recipe
it is based on). The `publish` job
runs `tools/win32-publish.sh` on tag pushes only.

Both read the code from this tree that the binaries carry from one list, `packaging/vendored.txt` (name, upstream,
licence, the files whose text goes into the notices, and when an entry applies only to some packages: `net`,
`dlss`, `fsr4cap`). The Windows package takes the entries without a condition, plus magic_enum and miniz, which
CMake fetches there. When a vendored component changes, change that list and `LICENSES.json`. The DLSS bridge and
AMD's FidelityFX API headers are in no release bundle: `build.sh` builds the bridge only with `DLSS_SDK_ROOT`, and
`fsr4cap.exe` is built on the user's machine or into the AppImage.

## Not in any bundle

OpenSSL, abseil and the online module (until kb #850), the Vulkan loader, GPL-encoder libraries, AMD's signed FSR 4
DLLs and model data, the FSR 4 v07 assets (`tools/fetch_fsr4_assets.sh` downloads them on the user's machine),
NVIDIA's DLSS SDK, game files and console system modules.
