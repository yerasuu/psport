# Changes 2026-10-04 — 2026-10-06 (version 0.3)

Measurements — RX 7800 XT / RADV, Mesa 26, 1080p output without FPS limit, unless stated otherwise.

## PC memory model — experimental, off by default

Enabled with the launcher toggle "New memory model (experimental)" or `BB_GUEST_IN_PLACE=1`; by
default the 0.2 model is used. Checked only on RX 7800 XT and Steam Deck, may crash; on NVIDIA the
dma-buf does not map with an offset, and the port falls back to the old model. The game's direct
memory is allocated through Vulkan
(dma-buf, GPU-visible system memory), and the GPU reads it in place, like a PC game's buffers. There
are no more copies of all memory into VRAM and no write tracking through page protection. Completion
labels (EOP/EOS) are written when the GPU has actually executed the work.

- Frames overlap: the first two command submissions of a frame (`BB_SUBMIT_AHEAD=2`) do not wait for
  the end of the previous frame. At K ≥ 8 the game heap leaks (~2 objects per frame), so there is a
  watchdog: growth of live allocations by 100 000 turns overlap off until the end of the session.
- Command submission is asynchronous (`BB_ASYNC_SUBMIT`): segment command buffers are closed by their
  recording threads, the submission itself is an ordered task on the same threads.
- GPU signals accumulate at the draw recording stage and are published in a batch; ConstRam waits are
  targeted.
- Measurements, Yahar'gul, standing: old model 138.7 → 143.6 FPS, new 101 → 152–155 FPS. Heavy spot
  (~2000 draws per frame): 95.5 → 115–124 FPS; there the limit is now the draw recording stage.

The settings keys `pc_memory` and `old_memory_model` are no longer read: the new key
`new_memory_model` is off by default for everyone.

## Video memory no longer grows from location to location

Before the fixes VRAM grew from 3.8 to 7.3 GB over 13 minutes of play, now it stays at 4–5.5 GB.

- **The texture collector freed nothing.** The ten oldest textures the GPU had rendered into used up
  the whole per-pass limit. Now such textures are skipped and moved to the end of the queue; without
  memory pressure, textures unused for `BB_GC_IDLE_SECONDS` (20) seconds are evicted. Age is counted
  in seconds: the former 16 command submissions (~3 frames) threw out everything that briefly left
  the screen.
- **Game memory blocks in VRAM were never freed.** Now blocks unused for `BB_VRAM_IDLE_SECONDS` (60)
  seconds are returned to game memory and moved to VRAM again on access (without this, a drop from 90
  → 55 FPS: the GPU read them over PCIe). Blocks of memory the game unmaps are freed. Free slots are
  also used by multi-block requests; new blocks take the fullest 64 MB chunks, nearly empty ones are
  evicted, empty ones are returned to the driver.
- VMA takes memory in 64 MB blocks instead of 256 (`BB_VMA_BLOCK_MB`), textures from 4 MB get a
  dedicated allocation (`BB_VMA_DEDICATED_MB`): deleted textures do not hold large blocks.
- Frame statistics: a `Memory:` line — the game's VRAM and GTT according to the kernel, RSS, VMA
  blocks, all Vulkan images, texture cache, game memory blocks in VRAM, collector activity.
  `tools/load_watch.sh` writes VRAM/GTT/RSS every 5 s.

## GPU hangs: the spot is found

GPU breadcrumbs (`vk_breadcrumbs.*`, `VK_AMD_buffer_marker`; `BB_BREADCRUMBS=0` — disable): before
and after every draw, dispatch and port pass the GPU writes the command number. On device loss the
log names the command the GPU stopped at, its shaders and parameters.

Found (session ~20 minutes): a hang in an indirect dispatch of the particle shader `cs 2da7fe60` right
after `cs 4ca76892` (1×1×1, emitter random number generator, counter in GDS). The loop iteration
count of `2da7fe60` is taken from memory. Indirect dispatch arguments are now copied by the GPU into
a CPU-visible buffer: the report shows what the GPU read, and the statistics the largest indirect
dispatches. **The cause is not yet fixed**: the next occurrence with this data is needed.

A hang no longer looks like a silent image freeze with sound playing (Steam Deck, fight with
Gehrman): GPU waits notice device loss, and a watchdog after 10 s without GPU progress writes the
breadcrumb report to the log and stops the game with a clear error.

## Crashes and launch

- Guest fault `0x263b8e7` (frequent on Steam Deck): EOP labels were written via `memcpy`, which
  writes 4–7 bytes as two overlapping words. The game managed to free the block between them. Now
  labels are written with a single atomic store (`store_once`, `StoreLabel`). Not checked on the
  Deck.
- NVIDIA with the new memory model crashed at launch: the driver does not map dma-buf with an offset.
  Before enabling the model the port checks this and on failure stays on the old model.
- Game file check (`scripts/game_check.py`, issue #7, #13, #14): the hash of the loaded eboot image is
  compared with CUSA03173 1.09; without the update, with an old eboot or another edition the launch
  stops with an explanation, the launcher shows the same. `BB_SKIP_GAME_CHECK=1` — bypass.

## Launcher and input

- Dropdowns with long options ("Background upload to video memory", GPU pipeline, GPU data reads,
  controller) show short names, and the explanation of the selected one as a line under the
  heading: text is no longer cut off.

- Controller selection (issue #15): *Controls → Controller* (`BB_GAMEPAD`, GUID or part of the name);
  the selected one is used as soon as it connects. List — `bb-gpu-capabilities --gamepads`.
- Character name entry in a window over the game (issue #19, patch from the issue); game input is
  neutral during that time (Backspace does not press the touchpad).
- The cursor is hidden in fullscreen and after 3 s without mouse movement in a window (issue #3).
- **Keyboard and gamepad remapping**: *Controls → Keyboard / Gamepad*, the "Assign" button waits for
  a press. In `bbport.ini` — `key.<button>=` and `pad.<button>=` lines with SDL names; no line —
  default binding.

## Game patches

- **Sprint Fix (High FPS)**: above ~147 FPS (and sometimes above ~90) running
  dropped to half speed — the game's wall detector measured distance per frame. The patch is always
  enabled together with the 90 FPS and "unlimited" modes.
- **Black tonemapping on Intel processors** (darker than on PS4; strongest in the DLC): the game code
  runs natively, and Intel's approximate float instructions give different values. The fix patch is
  enabled automatically on Intel processors; `BB_INTEL_TONEMAP_FIX=0/1` — forced.

## Upscalers: blur and stripes on stairs

- **Camera vectors: flipped vertical.** `camera_motion.comp` and the depth test in `taa.comp` assumed
  the view +y axis points up the screen; in the game it points down (along rows). The error affected
  camera pitch and vertical motion, left-right turning was correct. So it was visible where the
  camera bobs up and down: on the stairs to the cathedral from the Tomb of Oedon and in the sewers.
  FSR 4 and 4.1.1 gave striped blur, FSR 3.1 general blurring, while the character with object
  vectors stayed sharp. Check: on static meshes that also have object vectors (vertex positions from
  the GPU), the new camera vectors match them within 0.05 px over 17 frames of running up the
  stairs, the old ones diverged by 1.3–3.7 px. In game on FSR 4.1.1 1080p Performance "much better
  now".
- **16x anisotropic filtering** for scene draw textures (`BB_ANISO`, default 16; 0 — the game's
  filters). The game sets 1x on most textures, and with upscaling surfaces at a steep angle lose
  detail. On-the-fly A/B toggle — bit 61 in `BB_TOGGLE_FILE`.
- The upscaler dump (`BB_DUMP_TRIGGER`) also works on the HDR path, writes the frame's camera
  matrices; `tools/dump_view.py` converts the dump to PNG.

## MangoHud: double overlay

MangoHud text was doubled with an offset and different values: two overlays were drawn. The layer
built into the AppImage is called `VK_LAYER_MANGOHUD_overlay_64_x86_64` (nixpkgs), the system one is
named differently, and the Vulkan loader loaded both. On Steam Deck in game mode the same happens
with Steam's performance overlay (mangoapp) and MangoHud from the launcher. Now `run.sh` with
`MANGOHUD=1` does not enable MangoHud in game if mangoapp is running, and disables the built-in layer
if the system has its own (`VK_LOADER_LAYERS_DISABLE`). Not reproduced on NixOS without a system
MangoHud.

## Occlusion culling (rainmakerv3/shadPS4 branch `opts`)

The "correct queries" commit replaces the fake ZPASS_DONE counter with real Vulkan occlusion queries.
In Cathedral Ward Bloodborne makes ~0–8 such queries per 5 s and does not use predication
(`SET_PREDICATION` — 0), so it does not cull draws by them: nothing to port. The network thread in
offline mode (the epoll commit in the same branch) does not occupy a core for us.
