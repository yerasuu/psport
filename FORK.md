# psport: what this fork adds to bbport

psport is decanter's fork of [bbport](https://github.com/deadinside28/bloodborne_pc). Its goal is
bbport's own idea taken past one game: PS4 titles run natively on Linux, their x86-64 code on the
CPU as it is, with the system libraries provided by this port (a compatibility layer, as Wine is,
not an emulator). Bloodborne keeps working as upstream ships it; other titles start with
`BB_SKIP_GAME_CHECK=1`.

Upstream releases are merged in as they come; the changes below live on top.

## System modules

`BB_SYS_MODULES=<folder>` links the user's own dump of the console's system modules (`*.sprx`) that a
title needs. They are never part of this repository or of anything built from it, and each is a
stopgap until the port implements its library: `BB_HLE=libSceX` keeps one to the port,
`BB_LLE=libSceFiber` links one the port already implements, to compare the two.

`BB_SYS_FONTS=<folder>` likewise reads the user's own dump of the console's system fonts (SST and the
rest). Without it libSceFont draws each font set with the host's Noto fonts (`BB_FALLBACK_FONTS`
adds folders to look in) and logs the file it chose once per set.

## Modules the game loads

Modules a title loads itself with `sceKernelLoadStartModule` (every `*.prx` outside `sce_module` and
`sce_sys`, such as Unity's `Media/Modules` and `Media/Plugins`) are linked into the image at start like
the others, relocated and bound, but left unstarted: loading the path runs their initializer once and
returns their handle, `sceKernelDlsym` finds their exports (and the eboot's, handle 0) by name, and
imports of other modules bound to them, which the PS4 linker would rebind at that point, already
point at them.

## Diagnostics

| Variable | What it shows |
|---|---|
| `BB_PERMISSIVE=1` | imports the port lacks return 0 instead of stopping, each logged once |
| `BB_PERMISSIVE_OUT=error` | with `BB_PERMISSIVE=1`, those of them that write through a pointer argument (`src/import_outparams.inc`) return `0x80020016` instead of 0, so the game takes its error path rather than reading an output nothing wrote; either way their log line names the output arguments left unwritten and the pointers passed |
| (always) | before the game starts: every import without implementation or answered by a stub, and a summary |
| `BB_AUDIO_STATS=1` | per audio port, every 5 s: cadence, peak and RMS in dBFS (sound or silence) |
| `BB_NGS2_TRACE=1` | first calls of each Ngs2 function and the level of each render |
| `BB_FIBER_TRACE=1` | first calls of each Fiber function with their arguments |

## Regression runs

`tools/regress.sh` runs every title in `tools/regress/titles.txt` headless and says how far each
got, so a change can be checked against all of them at once:

```
SYS_MODULES=<folder> tools/regress.sh [-j 2] [-o out/regress/<time>] [-c <earlier results.json>] \
    [-n ryza,bloodborne] [-s <toolchain nix file>] <games root>
```

Each title runs inside a headless gamescope with `BB_AUDIO=none`: no window and no sound on the
desktop. Its pad schedule (`tools/regress/*.sched`: `<second> shot`, `<second> press <a+b> [hold]`,
`<second> end`) drives `BB_PAD_FILE` and takes frame dumps; a last one is taken before it stops. At
most `-j` titles (default 2) run at once. The titles file names the folder under the games root and
the title's own environment; `$NAME` there comes from the caller's environment, and a title whose
variable is empty is skipped (`$SYS_MODULES`: the folder of system modules above).

Milestones, from the log and the dumps:

| Milestone | Evidence |
|---|---|
| loaded | `Mapped N bytes, N segments` |
| entered | `Entering original x86-64 code` |
| initialized | the first `Runtime: guest thread '...' created` |
| gpu | `Presenter: first game frame presented` |
| frames | a present dump with at least 0.5 % of its pixels lit (a channel above 24 of 255) |
| audio | a `BB_AUDIO_STATS` peak above -60 dBFS |

It also records the first fault or stop logged before the title is told to end (`Guest fault`
offset, `Host fault` library+offset and function, `STOP:`, assertion; what a game logs while it
loses its display at the end is not a crash) and the summary's count of imports without
implementation. The table goes to stdout, `results.tsv` and `results.json` to the output folder
with each title's log and dumps (`tools/regress/report.py <folder>` classifies a folder again).
With `-c`, a milestone lost or a crash signature that is new or different is a regression: it is
listed and the exit status is 1.
