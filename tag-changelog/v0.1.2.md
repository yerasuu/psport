psport v0.1.2

GPU buffer failures fall back instead of asserting (decision #791), and the Windows port's groundwork
(#614): the platform layer, a build of `psport.exe` and the GPU library, and a Proton helper. Windows
is not a supported platform: `psport.exe` starts under Proton, creates its window, the Win32 Vulkan
surface and a swapchain on RADV, and stops at the guest-memory check (`Guest memory: direct memory
cannot be shared with this driver`); every `WIN32` row of
`host_features.inc` is `EXPERIMENTAL` or `UNAVAILABLE`. No change to the launch interface.

GPU (`gpu/shadps4/video_core/`)
- `UniqueBuffer::Create` returns false instead of asserting: a buffer VMA cannot allocate is tried
  again without `VMA_ALLOCATION_CREATE_WITHIN_BUDGET_BIT` while `TextureCache::NoteVramShort` evicts;
  one that still fails or has device address 0 stays null (`Buffer::IsAllocated`); `BufferDeviceAddress`
  returns 0 and `StreamBuffer::Copy` nullopt on a failed map.
- Null buffer: copies, fills, updates and image transfers are skipped; draws and dispatches binding
  one are skipped (GDS, page table, fault buffer, null index buffer, stream-out counters, indirect
  guard) and reset their bindings.
- Mirrors that cannot be allocated leave their blocks in place; a chunk buffer leaves its ranges to the
  arena and is created again once a second; a demotion without a chunk buffer keeps its blocks in VRAM
  until the next submission.
- `vk_staging_buffer_pool.cpp` frees idle ring blocks and dedicated buffers, retries, then waits for
  the GPU on a ring block (never inside the submit callback or a pending operation); else a null
  buffer that detiling, tiling, image downloads, readbacks and uploads skip, leaving their ranges
  CPU- or GPU-modified (an image left undetiled stays dirty); page table entries go in the command buffer.
- Occlusion queries (`vk_occlusion.cpp`) and GPU timestamps (`vk_timestamps.cpp`) without buffers are
  written by the CPU.
- Failures logged with `LOG_ERROR_COUNTED` (`buffer.cpp`, `vk_staging_buffer_pool.cpp`); an arena
  without device address stops the launch as `PsGuestMemory::Unsupported`. `FORK.md` row "GPU buffer
  creation failures that asserted".

GPU frontend (`gpu/shim/window.cpp`)
- `WindowSDL` accepts SDL's `windows` video driver (`#if defined(_WIN32)`): window type `Windows` with
  `SDL_PROP_WINDOW_WIN32_HWND_POINTER` as the handle, for `vkCreateWin32SurfaceKHR`; Linux builds
  do not include it.

Windows platform layer (`src/platform/win32/`, all `EXPERIMENTAL`, not run with a game)
- `host_memory.c`: guest arena as one `VirtualAlloc2` placeholder (`ps_host_vm_reserve_arena`, taken
  by `runtime_memory_reserve_arena` over `[0x0800000000, 0xfc00000000)`), fixed mappings carved into
  it as `MapViewOfFile3` views of `CreateFileMapping2` sections; `SEC_RESERVE` fallback past the commit
  limit; `CreateFileMappingW` where Wine lacks `CreateFileMapping2`, resolved at run time and logged.
- `host_fault.c`: first vectored handler, own setjmp/longjmp (SEH cannot unwind guest frames),
  interrupts by suspend and redirect below the red zone, resumed with `xrstor` and `iretq`; checked
  under Proton with a test program.
- `host_file.c`: `CreateFileW` handles behind psport's descriptor table, wide paths, `\\?\` past
  `MAX_PATH`; `host_process.c`: exec as `CreateProcessW`; `host_net.c`: Winsock 2, no socket pairs
  (`EOPNOTSUPP`, counted); `posix_compat.h` supplies what UCRT lacks.
- `ps_host_*` additions: `ps_host_env_set`, `ps_host_backtrace`, `ps_host_time_zone_at`,
  `ps_host_fs_stat_stream`, `_sync_stream`, `_truncate_stream`, `ps_host_remove_tree_at_exit`, interrupt masks.
- `runtime_socket.c` (`recvfrom`/`sendto`, `socketpair`, readiness), `runtime_trophy.c`
  (`trophyset.json` streamed into `<path>.tmp` and renamed), `runtime_ult.c`, `runtime_mutex.c`
  (`pthread_cond_clockwait`) changed to go through `ps_host_*`; Linux behaviour meant unchanged, listed
  in `docs/en/ARCHITECTURE.md`.
- `game_info.c`: install folder is `PS_INSTALL_DIR`, else the nearest folder above the executable
  holding `patches/` (was two folders up).

Windows builds
- `build.sh` `MINGW*`/`MSYS*` branch (CLANG64 only) builds `out/psport.exe`, `libpsport-gpu.dll` (no
  PGO, `-DPS_NET=OFF`) and `psport-gpu-capabilities.exe`; the DLL imports the runtime's symbols from
  `gpu/port/psport_runtime.def`; `psport.exe` links with `--disable-high-entropy-va`.
- `.github/workflows/windows.yml`: `windows-latest` job in MSYS2 CLANG64 on pushes to `develop` and
  `main`; artifact `psport-windows-<commit>` (14 days, `BUILD-STATUS.txt`), nothing published
  (decision #623).
- `tools/win32-cross.sh` (`sysroot`, `build`, `runtime`): local cross build with nixpkgs' clang over
  the CLANG64 packages in `PS_WIN32_SYSROOT` (#777).
- `tools/win32-proton-run.sh EXE [ARGS...]`: runs a build under Proton with `umu-run`
  (`PS_WIN32_PREFIX`, `PS_UMU_RUN`); ends the prefix's Wine processes with `wineserver -k` once
  `runinprefix` returns and passes the program's exit code.
- xbyak 7.43 vendored verbatim in `gpu/third_party/xbyak`, taken from there on every system (no
  longer from the Nix shell); listed in `packaging/licences.nix` and the README (BSD-3-Clause).
