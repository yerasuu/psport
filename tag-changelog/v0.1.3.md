psport v0.1.3

libSceNet starts from libSceNpManager's module start, draw preparation resyncs with the GPU thread's
registers (#887, #888), the loader reports imports that match only ignoring versions (#881), GPU
arenas are sized from maxBufferSize (#477, #848), shaders that run vector code under a constant EXEC
run in fewer lanes (#575, `ShaderBinaryVersion` 15), CPU writes of whole pages drop GPU data instead
of reading it back (#740), AvPlayer and Videodec2 misuse is logged instead of asserting, and the
Windows test package gets psport's own LGPL FFmpeg (#905, #906) beside the probe of GPU memory
sharing (#899). Windows is still groundwork, not a supported platform: nothing in this version runs
a game there. `psport.exe` now starts from the package, since FFmpeg is the LGPL build (verified under
Proton; the CI path is unverified). No change to the launch interface; the new variables
`PS_LOOSE_IMPORT_VERSIONS`, `PS_GPU_WRITE_OVERLAP`, `PS_SCALE_REDUCED_TARGETS` and
`PS_JOB_STEP_PROBE` are off by default.

Validation
- Included without complete validation: #740 (the harness could not measure its effect: its
  readbacks steps produced no CSV; a manual offline run dropped about 13 overwrites/s; the
  online-messages case was not tested) and #796 (no effect on develop alone; it only matters with
  P7, #370).
- Test runs of the integrated tree (measured by the night harness, not derivable from the tree): regress of the 13
  titles equal to the base (no crash, no unimplemented call, no forced submit; `altdeus` without frames as before);
  Bloodborne in play 220-225 FPS, GPU 4.15-4.19 ms, worst frame 7.1-7.6 ms (three quiet runs);
  validation with sync in play: no VUID, 10 SYNC-HAZARD-WRITE-AFTER-PRESENT (the same as the base);
  `VUID-VkBufferCreateInfo-size-06409` 4 to 0 (#477); Octopath 0: no SRT walker fault, prepared pipelines
  used about 20500 of 21500 in the first phase (#888); Blood Omen 2: no guest fault or hang in the regress (the shader of #575 is not logged, so its translation is not confirmed) (#575).
- Not exercised by the harness: the video error lines of #831, #592 and #593 (movies do not play in the
  scripted runs: no new line appears), #595, and #787, #683 with their variables beyond their start lines;
  #740: the harness runs do not stream resources (0 overwrites dropped); the manual offline session dropped 13.2
  writes/s with 16400 readbacks left (5.7 s of waits in 661 s); no baseline of develop without #740 exists.
- Cost of an opt-in: `PS_GPU_WRITE_OVERLAP=1` (#685) took Bloodborne in play from 224 to 20 FPS (GPU 30.5 ms
  against 4.2 ms), so it stays off by default.
- Every title rebuilds its shader cache once (`ShaderBinaryVersion` 15, #575).

Network (`src/system/runtime_np.c`, `src/loader/loader_link.c`, `src/kernel/runtime_module.c`)
- `runtime_np_manager_start` (once per process, `pthread_once`): `net_init`, `net_pool_create`
  `"SceNpSdkClient"` (0x4000 bytes, id `NET_POOL_ID_BASE` 3000), `ssl_init` (0x40000 bytes, context
  id 1), `http_init`; logs `Runtime: libSceNpManager started: net pool %d, SSL context %d, HTTP
  context %d`. A pool created afterwards (NpToolkit2's) gets 3001 and the next SSL context 2.
- Called before the module start of the first module whose imports list `libSceNpManager`
  (`needs_np_manager`, `has_np_manager_dependency` in `RuntimeModule`), and for the eboot only when
  libSceNpManager is not linked as a system module, which runs its own module start.
- `net_pool_create` and `net_pool_destroy` fail with `NET_ERROR_ENOTINIT` (0x804101C8, errno 200)
  before `net_init`, so a process that does not link libSceNpManager keeps the answer it had;
  `sceNetPoolCreate` also checks name (`CB_NET_POOL_NAME` 32), size (`CB_NET_POOL_MIN` 0x1000) and
  flags (`NET_ERROR_ENAMETOOLONG`, `NET_EINVAL`), 32 pools (`NET_ERROR_ENFILE`); 128 SSL contexts.
- `sceNetInit`, `sceNetTerm`, `sceNetPoolDestroy` and `sceSslTerm` stubs removed from
  `runtime_services.c`; `net_term` answers 0 and leaves the library initialized. First 16 failures
  logged (`log_library_failure`, `LOGGED_LIBRARY_FAILURES`), all counted in the call report.

Loader (`src/loader/loader_link.c`)
- Exact (NID, library, module, versions) binding unchanged. An import only an export of other
  versions would serve (`match_ignoring_versions`, index `versionless_map` keyed by NID, library
  and module names) is logged once: `Loader: import ... only ignoring versions: left to the host
  runtime (PS_LOOSE_IMPORT_VERSIONS=1 binds it)`; several candidate exports are `ambiguous` and never
  bound.
- `PS_LOOSE_IMPORT_VERSIONS=1` (`runtime_env_flag`, default 0) binds the single match. After the
  call report: `Loader: summary: <n> imports match an export only ignoring versions: <n> bound,
  <n> left to the host runtime (<n> ambiguous)`.
- Over 612 modules and games, none of 53 190 resolved imports matches only ignoring versions
  (kb #881): current games link as before.

GPU, draw preparation (`gpu/shadps4/video_core/renderer_vulkan/vk_draw_prep.cpp`, `gpu/diag/psport_srt_faults.cpp`)
- The draw preparation scanner (`ScanPacket`, `ScanCommands`) follows nested `INDIRECT_BUFFER`s up
  to `MaxNestedDepth` 4, copying them under a recovery point (`CopyGuestWords`) and keeping their
  state packets in `nested_words` for the workers. A buffer it cannot read, nesting deeper than 4
  and a `COND_EXEC` over packets that change registers end the scan of that buffer
  (`is_end_known` false): its later draws are not prepared.
- `RebaseTail` (`m_tail_epoch`, `m_is_tail_known`) takes the GPU thread's registers: after a buffer
  with unknown end state, and when `start_checksum` differs from the GPU thread's register checksum
  (a compute queue writing SH registers, anything not replayed), when the submissions from there are
  replaced by fresh copies and scanned again. The call-report line counts `resyncs after a buffer
  with unknown end state`, `after a register checksum mismatch` and `nested buffers replayed`.
- `SrtWalkerSignalHandler` (`flatten_extended_userdata_pass.cpp`): on a thread with
  `g_p_runtime_fault_recover` set (draw preparation workers, the draw pipe's table check) the fault
  abandons the walk and leaves the draw to the GPU thread (`PsSrtFaults::NoteAbandoned`,
  `AbandonedWalks`; counted in `SRT walker faults: summary: ... <n> speculative walks abandoned`,
  warning at every power of two).
- The diagnostic prints the load's effective address (`rdi` + displacement through
  `Common::GetRegister`, since a non-canonical address faults with 0) and both user data registers
  unmasked (`{:#018x}`).
- Octopath 0 (#888), measured in a test run of develop (not derivable from the tree): SRT walker
  faults 122728 to 0; prepared pipelines used 0 to 20578 of 21504 (95.7%); 0 resyncs, 0 abandoned
  walks, 122044 nested buffers replayed. Bloodborne with 0 faults.

GPU, arenas (`video_core/buffer_cache/buffer_cache.cpp`, `buffer.cpp`, `vk_instance.h`, `gpu/memory/psport_guest_memory.cpp`; #477, #848)
- `BufferCache` constructor: `m_cb_max_arena` = `max(Instance::MaxBufferSize(), 1 GiB)`,
  `m_arena_page_bits` = `min(32, bit_width(m_cb_max_arena) - 2)`, `m_c_max_arena_pages` =
  `m_cb_max_arena >> m_arena_page_bits`; was `ARENA_PAGE_BITS` 32 (4 GiB pages, 4-8 GiB sparse
  buffers over RADV's maxBufferSize of 4 GiB - 4, VUID-VkBufferCreateInfo-size-06409). On RADV:
  pages of 1024 MiB, at most 3 per arena; with a maxBufferSize of 8 GiB or more, 4 GiB pages, at
  most 2. Startup line `GPU memory: maxBufferSize ..., arena pages of <n> MiB, at most <n> pages`.
- `GetArena` takes a span of any size and returns null (counted, logged) when the span needs more
  than maxBufferSize or the arena cannot be created; `GetArenaClamped` lowers `last_block` to what
  one arena covers; `NullBinding` (64 KiB, contents undefined) for a binding without an arena.
  Spans over the limit get arenas of their own pages (`ArenaSpan::Split`), are clamped
  (`Clamped`) or left without (`Failed`); frame-stats line `Buffer arenas over maxBufferSize: <n>
  ranges given their own pages, <n> clamped, <n> without an arena` (`g_c_arena_spans_split`,
  `_clamped`, `_failed`).
- `StopWithoutArena` removed: `UniqueBuffer::Create` returns false and logs `LOG_ERROR_COUNTED`
  (`Sparse arena of ... bytes not created: it cannot take exported memory (...)` or `... cannot
  take VRAM`) instead of `PsGuestMemory::Unsupported` stopping the launch.
- `FitsInBuffer` (`psport_guest_memory.cpp`, `s_cb_max_buffer` from `MaxBufferSize`): a guest
  memory chunk over maxBufferSize gets no buffer and stays in the memfd; logged at every power of
  two (`Guest memory: chunk ... exceeds maxBufferSize`).

GPU, shaders and pipelines (`gpu/shadps4/shader_recompiler/frontend/control_flow_graph.cpp`, `vk_pipeline_serialization.cpp`; #575)
- `SetsExecToConstant`: `S_MOV_B64` to `ExecLo` from `ConstZero`, `SignedConstIntPos`,
  `LiteralConst` or `SignedConstIntNeg` other than `SignedConstIntNegMin` opens a divergence scope
  as a saved mask or `IsCmpx()` does, so a one-lane atomic add (`s_mov_b64 exec, 1`) no longer
  runs in 64 lanes. Seen in Blood Omen 2's emulator dispatch, which now finishes.
- `ShaderBinaryVersion` 14 to 15: every title rebuilds its shader cache once.
- Preloaded pipelines with crossed motion shaders (`HasMotionMismatch`, `IsMotionStage`): shader
  metadata is keyed by `HashCombine(pgm_hash, perm_idx)`, so a motion permutation left out of a
  preload lets a normal one take its index. Such a pipeline is not preloaded; counted in
  `m_c_motion_mismatches` and logged once at `WarmUp`: `Pipeline cache: <n> graphics pipelines not
  preloaded, their motion vectors setting differs from their cached shaders'`. No effect without
  P7, #370 (#796; see Validation).

GPU, memory and images (`vk_rasterizer.cpp`, `texture_cache.cpp`, `vk_temporal_upscaler.cpp`, `vk_camera_motion.cpp`)
- CPU overwrites (#740): `runtime_memory_prepare_overwrite` (`src/kernel/runtime_memory_gpu.c`,
  exported in `gpu/port/psport_runtime.def` with `runtime_memory_set_overwrite_hook`) is called
  before `memcpy`-style copies (`prepare_copy` in `src/runtime/runtime.c`, skipped when source and
  destination overlap), fills and Bloodborne's copy hook (`gpu/games/bloodborne/guest_hooks.cpp`)
  when a watched page (`s_p_write_watch`) lies wholly inside the range. The hook calls
  `Rasterizer::PrepareCpuOverwrite` then `BufferCache::DropOverwrittenGpuData`, on the GPU command
  thread (not from a GPU-side thread, nor with the layer's mirrors or readbacks disabled): GPU data
  in the whole pages whose GPU writes are done (`WriteTicks().Newest`, `scheduler.IsFree`) is
  dropped and the pages become CPU-modified, instead of a wait and a download at each write fault.
  Partial pages and pending GPU writes keep the readback.
- Frame-stats line `GPU data overwritten by the CPU: <n> writes/s dropped it instead of a readback
  (<n> MB/s of whole pages), <n> page runs/s kept for one (GPU write not done)`
  (`g_c_overwrite_drops`, `g_cb_overwrite_drop`, `g_c_overwrite_drops_kept`).
- `PS_GPU_WRITE_OVERLAP=1` (default off, #685): a shader binding that writes memory calls
  `TextureCache::WriteBackImagesUnder` (images with texels their memory lacks, through
  `BufferCache::WriteBackImage`) before it is resolved and `InvalidateImagesUnder` after, marking
  every image over the range `GpuDirty`; before, only an image starting at the binding's address.
  Failed write-backs are counted (`LOG_ERROR_COUNTED`).
- `PS_SCALE_REDUCED_TARGETS=1` (default off, #787): `SceneTargets::IsIntermediateTarget` gives live
  scene scaling proxies to color targets from a quarter of the scene size up to it that are not the
  post size and not power-of-two on both sides (Bloodborne's depth of field, 1176x441); proxy size
  is the size times the scene factor, rounded (`std::lround`). Depth, smaller reductions and LUTs
  keep the native size. Documented in `docs/en/upscaler.md`.
- `TextureCache::HasImage` (slot allocated and `ImageFlagBits::Registered`): `TemporalUpscaler::KeepsLive`
  and `CameraMotion::KeepsLiveDepth` forget a kept image id freed since an earlier draw of the frame
  (`Upscaler: <role> image <n> freed during the frame, forgotten`, `Camera motion: scene depth <n>
  freed during the frame, forgotten`, `LOG_ERROR_COUNTED`); it was read through its erased slot
  and crashed in `TouchImage` (#595, Bloodborne's lamp travel).

Video (`gpu/shadps4/core/libraries/videoout/`, `avplayer/`, `videodec/`)
- `VideoOutDriver::Flip` clears the previous buffer's label (`buffer_labels[prev_index]`,
  `vo_cv.notify_one`) and sets `prev_index` under `vo_mutex` before the flip event; it ran after
  the events and outside the lock, so a game locking that buffer again right after the event could
  lose its new label before its flip IRQ read it (Bloodborne's death screen, exit 23, #593). The
  IRQ reads the label under the lock too, and a flip dropped by a full queue releases its label
  (`video_out.cpp`).
- AvPlayer uses the FFmpeg stream index `EnableStream` stores (`m_video_stream_index`,
  `m_audio_stream_index`) directly in `Start`, `DurationMillis`, the loop seek and
  `PrepareVideoFrame`/`PrepareAudioFrame` instead of indexing `m_streams` with it again, which only
  holds the supported streams (wrong stream and edit delay, or a read past `m_streams`; #592). The
  index check is against `nb_streams`.
- Seven assertions of AvPlayer and Videodec2 are `LOG_ERROR_COUNTED` (call-summary counts): an
  unknown stream type keeps type `Unknown`; a null game frame buffer (`GuestBuffer::GetBuffer`)
  makes `sceAvPlayerStart` fail with `ORBIS_AVPLAYER_ERROR_OPERATION_FAILED`; a video frame not NV12
  or not fitting its buffer (`Videodec::CopyNV12Data` returns bool), an audio frame not S16 or over
  1024 samples or its buffer's bytes, and a failed S16 conversion (null before) stop that decoder and
  call `m_state.OnError()`; `sceVideodec2GetPictureInfo` with `picture_count` above 1 copies the
  first picture info, returns `ORBIS_OK` and logs `(STUBBED)`.

Bloodborne diagnostics (`gpu/games/bloodborne/job_step_probe.cpp`)
- `PS_JOB_STEP_PROBE=1` (default off, #683): `PsJobStepProbe::PatchImage` detours the render job
  step's two failure exits (usage check 0x2165150 at image offset 0x1067fff, result 8; scratch block
  request 0x2169c30 at 0x1068036, result 9); `OnFailure` logs the first 16 (`LoggedFailures`) and
  each power of two, `Report` prints `Job step probe: <n> failures of the <check>` per frame-stats
  window. Code only under `gpu/games/bloodborne`.

Windows platform (`gpu/memory/psport_guest_memory.cpp`, `src/platform/host_features.inc`)
- When the host import of the shared view fails, `ImportsPrivateMemory` tries private memory and
  the reason says so (`private memory imports: the driver takes anonymous memory only, and direct
  memory is mapped at several addresses through views of one shared memory`); the mode chosen is
  the same. The view is named `view of a section` on `_WIN32` and `memfd mapping` elsewhere.
- `host_features.inc`: `gpu_memory_host_import` `WIN32` `EXPERIMENTAL` (#870): under Proton on RADV the
  import of section views fails with `ErrorInvalidExternalHandle` and private memory imports; not
  run with a driver that imports views (NVIDIA, native Windows).

Windows test package (#899, all `EXPERIMENTAL`)
- `tools/win32_probe/` (`main.c`, `system.c`, `vulkan.c`, `memory_tests.c`, `probe.h`), built by
  `build.sh` as `out/psport-windows-probe.exe [--output PATH]`: writes
  `psport-windows-report.txt` next to the program (`%TEMP%` when not writable) with the system,
  each Vulkan device's capabilities and memory, and the tests of 1 MiB per device: `[a]` host import
  of private `VirtualAlloc` memory, `[b]` `MapViewOfFile` view of a pagefile section, `[b2]`
  `SEC_RESERVE` one, `[c]` `MapViewOfFile3` view in a placeholder, `[d]` two views of one section
  imported at once, `[e1]` `OPAQUE_WIN32`, `[e2]` `OPAQUE_WIN32_KMT`; an import passes when the GPU
  reads what the CPU wrote and the CPU sees what the GPU wrote. Ends with a verdict (`verdict_for`)
  on the guest-memory mode for the device psport takes.
- `tools/win32-bundle.sh DEST` writes `psport-windows-<version>-<commit>-x86_64.zip` and `.sha256`:
  `psport.exe`, `libpsport-gpu.dll`, `psport-gpu-capabilities.exe`, `psport-windows-probe.exe`,

  found from the PE import tables (`llvm-objdump`), each checked against an allowed-licence list
  of its package (GPL-2.0-compatible only). Next to the zip, `psport-windows-<version>-<commit>-x86_64-sources/<pkgbase>-<version>/`
  (`ship_sources`) holds the PKGBUILD and upstream tarball of each DLL built from
  `packaging/windows/*/PKGBUILD`, checked against the PKGBUILD's `sha256sums`; `SOURCES.txt` points
  there.
- FFmpeg (#905, #906): `packaging/windows/ffmpeg/PKGBUILD`, package `mingw-w64-ffmpeg-lgpl`,
  FFmpeg 9.0.2 (`pkgver`, `pkgrel` 1) from the unmodified release tarball (sha256 in `sha256sums`,
